# Architecture

**English** · [简体中文](architecture.zh-CN.md) · [Documentation](README.md)

Glim is a focused file viewer for macOS on Apple Silicon and Intel. Readers share a tabbed workspace. Ordinary UTF-8 text supports basic editing and autosave; diffs, historical content, images and binary/document previews are read-only.

## Floating reader actions

`reader/controls` supplies bottom-center, content-overlay capsules for CSV/Geo tables, paged text/hex, book controls, XMind, image pagination and Markdown diagram batches. Titles, catalogs and sheet navigation remain separate. Scrollable content includes end clearance, and embedded book/source pagers offset their capsules to avoid overlap. GPUI capsules use theme-based translucency, borders and shadows; they do not implement backdrop blur or optical refraction.

`native/FloatingReaderToolbar.swift` supplies the matching AppKit surface for image/SVG, PDF, media, font, SQLite/XLSX and Office actions. It uses public `NSGlassEffectView` on macOS 26+ when built with a supporting SDK; SDK detection defines `GLIM_NATIVE_GLASS` in both native builds. Older SDKs/systems retain `NSVisualEffectView` without increasing the macOS 11 minimum. Wide native action sets scroll within the capsule; media controls leave AVKit's transport clear. SVG content stays in the isolated streamed image document; native buttons invoke only the wrapper's image commands. Common native toolbars omit file-byte and query-timeout retry actions; complete byte paging remains available in fallback readers. The unused file-byte polling bridge is removed. Visible control widths are measured from labels and selectors, with overflow handled by the capsule scroll viewport. Reader action capsules are invisible until the pointer dwells in a broad transparent bottom zone. Reveal and dismissal are delayed; pressed-button drags freeze visibility, and releasing a drag does not reveal controls. The hidden native zone passes clicks through to the document. They size to their visible controls; buttons retain bordered surfaces distinct from secondary status labels, and row/column paging groups appear only when needed.

## Modules and dependency direction

```text
crates/
  glim-core/src/       document/Git/update values, diff parsing and graph layout; no I/O or GPUI
  glim-services/src/   filesystem, Git, watchers, format parsing, backups and preferences; no UI
  glim-app/src/
    app/              startup, actions, menus, locale, diagram engine and updater coordination
    views/
      workspace/      windows, tabs, loading, navigation, editing and update-session restoration
      reader/         source, markup, data trees/tables, images, native previews, XMind and diffs
      changes/        repository operations, Changes and Graph
      explorer.rs     lazy directory tree, sticky ancestors and filename/path tooltips
      split_diff.rs   aligned diff panes and synchronized scrolling
      minimap.rs      document overview
native/               embedded macOS previews, settings helper and Sparkle bridge
assets/               branding, file icons, syntax queries, offline engines and bundle metadata
scripts/              packaging, signing, feed generation and focused native checks
```

Dependencies are one-way: `glim-app → glim-services → glim-core`; app may also use core directly. GPUI Kit is pinned and Cargo.lock retained. Blocking file/Git work runs on the background executor. Render methods compose cached state, not filesystem scans or commands. Views retain their entities, subscriptions and cancellable task handles.

## Shared reader policy

`assets/reader-limits.json` is the single source for application reading thresholds, organized by reader with typed values, units, effects and descriptions. `scripts/generate-reader-limits.py` validates it and generates Rust constants, Swift ReaderLimits and embedded JSON into each Cargo OUT_DIR. `glim-services::limits` exposes the Rust values; app presentation uses that module directly, native preview targets compile the generated Swift, and the private diagram WebView receives the same value map. Builds track the policy and generator, and CI path filters include both. No reader performs runtime policy-file I/O. See [the generated inventory](reader-limits.md); update it with the generator’s `--docs` option. Non-Git readers use streaming, paging or complete source fallbacks instead of total-file caps; Git/diff migration is deferred. Working budgets bound active processing, not access to complete files.

## Workspace and editing

Each window owns an implicit, independent workspace. Adding folders appends root entries in order, including repeated paths and parent/child paths; another window can add the same folders. Explorer tracks expansion, selection and element identity per root occurrence while sharing directory data by path within the window. Git repositories remain deduplicated by repository path. Top-level root context menus can remove an individual entry without deleting files or closing open tabs. Explorer emits a stable root identity; Workspace updates its roots, search scope, recent history, repository discovery and watchers. Removing the last root leaves open files watched independently and removes the empty workspace from recent history.

Workspace owns tabs, Explorer/Changes entities, navigation history and asynchronous loading. File tabs use paths as identity; diff/history tabs also include repository/scope/commit identity. Reopening activates an existing tab/window. Finder file opens use a retained queue for every format, including unsupported files; errors stay in tabs.

Workspace presentation uses the existing grayscale theme tokens: Start/Files navigation lives in the compact sidebar (20% of window width by default; double-clicking its resize divider restores that ratio, dragging below 120 px collapses it, and its maximum width is 50%); the Git entry is currently hidden, while the content surface begins directly with document tabs, including when only one file is open. `workspace/toolbar` owns the action definitions, reader-capability selection, ordering, icons, labels, selection/availability states, shared button rendering and action dispatch for the outer toolbar. It presents navigation first, document viewing/layout controls next, and update availability last; readers expose supported capabilities rather than toolbar code maintaining a separate file-extension allowlist. Sidebar/back/forward navigation follows the Glim brand and a divider in the outer title bar; reader-mode and word-wrap controls occupy its right side as uniform icon buttons. The title bar also owns sidebar visibility and a permanently visible search input centered on the window, with results anchored below it. Saving stays available through autosave, the menu and ⌘S; there is no save button or saved-status footer. Git repository state and the staged-only commit composer belong to the Changes panel, not a persistent workspace footer. These controls reuse the existing reader entities and asynchronous save/Git operations. `app/menus` owns the three macOS menus (Glim, File and View). About, Settings and an intentionally duplicated update-check entry live under Glim; refresh remains available through its shortcut, and File → Close Window closes only the current workspace; ⌘, opens Settings in the current workspace. `workspace/settings` owns the theme and language selectors plus default file-type management, update checks and keyboard-shortcut help. Language selection is cached in the app and applied without reading preferences during rendering. The theme selector provides System, Light and Dark choices. Services retain the appearance preference, and the app serializes its writes; each workspace retains an appearance observer to update the theme when macOS changes while System is selected. Sidebar density and reading size are fixed, and ordinary text autosaves without a settings toggle. Start and Settings hide native reader views without disposing document tabs.

The Start page lists up to 30 recent non-empty folder workspaces, with folder names and paths. The current window’s workspace is hidden. Clicking an already open workspace activates its existing window, including while its roots are still restoring; otherwise a new window restores its ordered roots, including duplicates, without restoring file tabs. Matching uses the history identity or the exact ordered root list, preserving duplicate-root counts. Services atomically persist this history in `recent-workspaces.json` and migrate the legacy last-folder list when history is absent. App owns the shared cached list and serialized background preference tasks; the welcome view renders only cached data. Each window updates its own history record as folders are added, and identical folder lists share one recent entry.

The document toolbar also provides per-window file fullscreen: it hides the sidebar, tabs and history summary, expands the active reader, and retains a compact title bar with viewing controls and an exit button. Escape exits this mode. Sidebar sizing/visibility and reader entities are preserved; macOS App fullscreen remains independent.

Closing a workspace window affects only that window and keeps its unsaved-change guard. The app uses explicit quit behavior: closing the last window leaves Glim running; reopening from the Dock creates a workspace window. File → Close Window (⌘⇧W) closes the current window; ⌘W closes its current tab or its empty window. Only Quit Glim / ⌘Q requests application-wide exit, with the existing update-install exit gate retained.

Folder roots are persisted atomically in `workspace.json`. Ordinary startup restores recent roots, not a complete general-purpose tab session or unsaved drafts. Update restarts additionally consume a one-time tab session; see [updates](auto-update-design.md).

Refreshes preserve reader state where supported and never replace a dirty draft. Obsolete task results are ignored after navigation; already-running blocking work may finish, but its result is not installed. Watchers coalesce events and monitor Git metadata for linked worktrees. Horizontal content scrolling takes precedence over navigation gestures.

`SourceReader` retains `EditorState` for typing, selection, undo/redo, search and folding. Tree-sitter handles supported grammars; lightweight visible-line coloring covers other configurations/templates without LSP. Autosave queues each file after approximately 800 ms idle and keeps explicit ⌘S/Ctrl+S. Same-directory temporary files provide atomic replacement; disk-baseline conflicts preserve the draft. Close/quit checks unsaved content and pending saves.

`reader/markup` uses TextView for Markdown and an embedded WebKit view for HTML. Preview and source share editing state; format-specific preferences survive refresh/reopen. Unchanged source reuses rendered state. HTML previews render CSS and JavaScript from the editor snapshot; the source editor remains available. JSON/CSV entities parse editor snapshots in retained background tasks; their read-only projections do not replace editable source. Markdown preview preparation in `services/markdown_preview` tolerates blank lines between explicit pipe-table headers, delimiters and matching rows. It uses top-level Markdown AST block ranges to preserve code, HTML, math and frontmatter, and changes only preview text. The editor and saved source retain their original bytes; preview images, diagrams and heading ranges use the same normalized text. CSV and TSV share a persisted reading-mode preference (`csv-view`); new ordinary and paged readers use the last selected table/source mode, while refreshing an existing reader preserves that reader’s mode. A rejected preview switch does not update the preference. When opening a CSV/TSV in table mode, the workspace replaces the old document with a centered preview-loading state during file reads; the table reader uses the same state during parsing and page loads. Existing reader entities remain retained, and errors follow the normal reader error path.

## Diagrams and format readers

`services/markdown_preview` parses/deduplicates diagram and formula blocks, invokes private `--render-markdown`, and rasterizes bounded SVG output. `app/diagram_engine` uses WebKit on its process main thread with bundled offline engines. Completed snapshots are published incrementally; cancellation terminates the renderer. macOS bundles a background `GlimRenderer.app` (`LSUIElement=true`); unbundled builds use the executable's renderer mode. Rendering does not depend on Node, Java or a remote service.

Mermaid, Graphviz, PlantUML, flowchart.js, WaveDrom and MathJax are embedded with their licenses. Local Salt/Chen adapters cover a subset of syntax. External diagram resources, navigation and downloads are blocked; failures preserve source. Engine source and bundled resources live in [scripts/markdown](../scripts/markdown) and [assets/markdown](../assets/markdown).

`services/formats`, `text_formats` and `vector_formats` supply bounded container listings/text extraction, basic reading projections and static mesh/bitmap-font images. Dedicated ebook reading belongs to `services/books` and `reader/books`; these generic projections do not execute document code. `services/media` decodes bounded images. Large standalone PNGs share the ImageIO thumbnail preparation in `services/inline_images`, reading from a temporary snapshot of the captured bytes so the preview and fingerprint stay consistent; workspace loading displays immediate status feedback. Its `GifPlayback` owns a sequential GIF decoder and bounded compositing/restore buffers; `reader/media::GifReader` retains a cancellable playback task, supplies individual BGRA frames directly to GPUI, and releases replaced textures. GIFs composite at original resolution, but displayed frames are bounded to a 2,048px longest edge. Playback uses absolute deadlines and two lookahead batches (each at most three frames / 16 MiB); expired intermediate frames are not uploaded. Frame disposal and finite loops are preserved without GPUI’s whole-animation image cache. Hidden tabs pause decoding; closing cancels playback and releases the current texture. Per-reader budgets and boundaries are maintained in [formats and limits](file-format-support.md).

`services/xmind` reads modern JSON or legacy XML from bounded ZIP content without extraction. Its UI-independent sheet/topic model includes notes, labels, floating roots and relationship endpoints. `reader/xmind` owns sheet selection, folding, zoom, scrolling and topic details; layouts are cached and GPUI paints visible nodes/links with theme tokens. The reader is read-only and uses ordinary loading, refresh and update-session paths.

## Embedded macOS previews

`native/Preview.swift`, `EmbeddedPreview.swift` and `SQLitePreview.swift` implement PDFKit, AVKit, Quick Look, CoreText, worksheet index and SQLite views embedded in workspace tabs. They do not launch separate preview apps or Dock icons. App build.rs compiles the Swift static library. `reader/native_bridge` owns the narrow main-thread-only unsafe FFI boundary and attaches NSViews to the GPUI AppKit window; the native-preview, context-menu and updater bridges are the app’s scoped unsafe exceptions, while remaining app code denies unsafe and core/services forbid it.

`services/matroska` validates bounded EBML structure and remuxes H.264/AAC-LC samples to a temporary MP4 for AVKit. AVC parameter sets come from track configuration or Annex-B frames; MP4 composition offsets preserve reordered frames. `services/preview` retains temporary media and maps original paths to playback paths, preserving file identity and labels. No FFmpeg installation or subprocess is required; see [format limits](file-format-support.md).

`services/preview::prepare` validates files and prepares playlists, database snapshots and disk-backed worksheet indexes off the UI thread. Each `reader/native` entity retains its controller and prepared data. Native framework loading is scheduled on the main queue rather than inside GPUI render/layout. Switching hides views and pauses media while retaining local page/playback position; closing releases native resources before temporary data. Toolkit overlays temporarily hide native views. Accessibility nodes and responder-chain actions are integrated into the main window.

SVG image previews reuse `HTMLPreview` and its streamed local-resource handler after service-side sanitization. A static image document owns one scroll viewport and fit/actual-size/zoom controls; SVG scripts and links do not execute. Raster images retain ImageIO. Image previews omit the file-byte footer. Raster scroll clips center documents on both axes when smaller than the visible area, and fit mode recomputes on viewport resize. Explorer and document-tab context menus use the scoped `views/native_menu_bridge` AppKit bridge, which tracks selections asynchronously and cancels on owner drop. These menus layer above native previews without hiding, pausing or replacing readers; only an explicitly selected action changes file/workspace state. Browser-image preparation preserves data-URI images (including nested SVG without rasterizing), XHTML `foreignObject` labels and complete stylesheets, while the SVG image sandbox prevents document scripts and external loads. Percent/missing root dimensions resolve from the viewBox (or the other absolute dimension) before zoom sizing.

PDF and Office/iWork remain read-only. `services/spreadsheet` streams XLSX relationships, shared strings and worksheet XML into a temporary SQLite index. A disk-backed worksheet-position cache generates bounded presentation workbooks for the selected row/column page. Native Quick Look uses its normal full-sized style, constrained to all four reading-area edges, to render those pages with cell styles, widths, heights, merges and cached values; formulas are not recalculated. The explicit Cell data mode retains the complete address/value/formula index. Presentation copies omit charts and drawings; shared-string rich text retains text but not per-run formatting. The private app helper performs page generation in a cancellable subprocess. Legacy XLS and unsupported workbook structures use Quick Look. Fonts are inspected, not installed. Audio artwork/metadata load asynchronously with cancellation; decorative playback animation respects reduced motion and is not a spectrum analyzer.

`services/sqlite` streams database/WAL/journal data into a private snapshot and checks source stability; SHM is rebuilt in the copy. Native SQLite runs generated read-only queries on a serial background queue with extension loading disabled. Sources are never checkpointed or written. Missing-main sidecars show bounded information.

`native/PreviewMain.swift` is only the separate default-file-type settings helper. It changes Launch Services handlers after explicit selection/confirmation, records old handlers, and does not overwrite a user's later changes during restoration.

## Directory discovery and Git

Explorer expands newly added roots one level, leaving descendant folders collapsed. It restores per-root expansion state from `explorer.json` during ordinary workspace restore and update-session restore; writes are atomic, serialized and awaited on quit. Tab activation reveals the active file by loading its ancestors in retained background tasks, selecting it and scrolling it into view; the latest requested file wins. Explorer loads direct children on expansion, honors ignore rules, hides `.git` and does not recursively follow symlinks. Cached background media checks control folder playback menus; rendering does not scan folders. Blank-space and row context menus are separate.

Repository discovery scans selected roots in background without arbitrary time/depth/count truncation. Generated/ignored directories are excluded; automatic home-level discovery skips macOS Library/Trash, while explicitly selected paths are scanned. Per-path failures do not discard other repositories. Diagnostics are bounded/deduplicated; watcher refreshes do not repeatedly open warnings.

Git uses argument arrays and literal pathspecs, clears repository-location environment overrides, and disables external diff/textconv/pager/fsmonitor. Output is bounded and stderr drained independently. User credentials, hooks and commit signing remain in use. Staging is explicit and commits use only the index.

Services revalidate HEAD/index/source state for writes. In-app editing/Git-write locks protect drafts across workspace windows but do not create a transaction with other Git clients. Pull is fast-forward only; branch deletion uses `-d`. No cloning, force pushing or destructive history rewriting is added.

Core computes Graph lanes from commit/parent IDs. History grows in 200-commit pages up to 1,000; unchanged history and overlapping refreshes preserve rows/scroll state. Merge previews compare the first parent; conflicted combined patches fall back to inline. Diff display bounds do not alter full-file staging. Side-by-side panes align original lines and synchronize vertical scrolling.

## Platform, preferences and update boundaries

The maintained workspace uses GPUI on macOS Apple Silicon and Intel with ⌘ shortcuts. Swift provides native previews and default file-type settings; diagrams use system WebKit. Windows application/service branches have been removed; the build script explicitly rejects non-macOS targets.

macOS bundle identity remains `io.github.jony4.glimpse` for compatibility. Preferences use `~/Library/Application Support/Glim`, with legacy Glimpse fallback where implemented. Locale dictionaries are embedded; document text and technical diagnostics are not translated. Each documentation topic has English and Simplified Chinese counterparts.

`glim-core/update` defines snapshots, modes, activity guards and session values. `services/updates` verifies/copies backups and writes/consumes bounded session checkpoints. `app/updates` owns one global `UpdateState`, task handles, editing locks and exit-generation checks; `views/updates` renders a reusable centered window. Menu/About/titlebar entries share that state. Finder opens arriving during exit preparation withdraw approval and preserve the file request.

The macOS `macos-updater` feature connects `app/updater_bridge` to Sparkle 2.10.0 in `native/Updater.swift`. Its custom user driver delegates install approval to Rust. The bridge adds the missing cancellable termination method to the fixed GPUI delegate without replacing it; incompatible future delegate contracts disable updating. Sparkle handles signed downloads, extraction, permissions and replacement. Unconfigured builds offer manual downloads. Only the two Mac architectures receive signed update feeds.

See [update behavior and trust](auto-update-design.md), [release setup](releasing.md#automatic-updates) and [remaining work](TODO.md).


## Markdown network images and executable inspection

`app/image_http` registers a GET-only GPUI image transport. Network and decoding work runs on the background executor through `services/markup_images`, with shared timeout, redirect and minimum-transfer-rate budgets, streaming responses into temporary files without a total download cap. The service returns bounded image data, uses system fonts for SVG, blocks external SVG resources and returns a visible placeholder on failure. GPUI owns static asset caching and refresh; render methods perform no network or file I/O. The maintained transport uses system curl on macOS and converts GitHub repository `blob`/`raw` image URLs to `raw.githubusercontent.com`, with a GitHub Contents API raw-media fallback for conventional ref/file URLs when the raw host fails. Both attempts share the configured network timing policy. The unauthenticated API fallback is subject to GitHub rate limits; link destinations and source text are unchanged.

`reader/pictures` retains cached theme candidates and cancellable parsing tasks. Markdown HTML nodes and HTML documents are parsed in the background. `reader/markup` selects picture sources for the current theme without rewriting editor contents, anchors or user files. `reader/pictures` also prepares one persistent sequential player per resolved `.gif` image URL (local or HTTP), shared by duplicate references. Markdown image resolution supplies its current frame directly through a custom GPUI image source, including while initially loading, so embedded GIFs bypass the whole-animation cache. Parsing ignores code examples; network/file work is background-only, removed references release players, and hidden/source-only previews cancel playback and release decoding buffers while retaining compressed GIF data; unfinished animations restart when shown again, and completed finite GIFs keep their final pixels. Unknown media conditions use the img fallback; conflicting candidates for the same fallback URL are left unchanged.

`services/inline_images` prepares static document-image previews with a maximum 2,048px edge, using the built-in macOS `sips`/ImageIO thumbnail path under a shared preparation lock. Rust only decodes the bounded thumbnail, avoiding full-size raster buffers in the viewer; remote inline rasters use the same path after the streamed download. Local SVG uses the bounded raster service. `reader/pictures` retains one `InlineImageReader` per resolved static URL and activates only the current theme candidate; hidden/source-only documents cancel preparation and release their pixels. Inline static previews may lose detail when enlarged, while source files and standalone image-reader limits are unchanged. Image-atlas eviction is deferred until the current rendering window has been returned to the app, so hiding a document also evicts that window's textures.

`services/executables` recognizes Mach-O, universal Mach-O, ELF and PE headers and uses object for read-only architecture, segment, section and available dependency metadata. A seekable metadata cache bounds active memory independently of file length; complete names are scanned incrementally. Metadata working-budget exhaustion falls back to complete hexadecimal pages. Inspected programs are never loaded or executed. `workspace/loading` routes this content into the existing read-only byte reader before attempting text decoding, without separate preview windows.

## Ebook reading

`services/books` reads bounded EPUB package metadata/spines and EPUB3 nav or EPUB2 NCX, FB2/FB2 ZIP structure and embedded illustrations, and naturally ordered CBZ pages. Chapters are loaded and sanitized on the background executor; XML entity declarations, archive path escapes, scripts and automatic external resource loads are rejected. Image previews have per-chapter encoded/decoded budgets. Resources stay in memory and are not extracted into document directories.

`reader/books` retains chapter parse entities, resource images, focus/scroll handles and cancellable loading tasks across renders. Its book surface supplies serif/sans-serif typography, font size, line height, page width, paper tint, TOC, chapter/page navigation, bookmarks and position restoration. Preference writes are serialized through a retained task and a coalesced state buffer; update exit checks wait for book writes as well as ordinary file work. `books/preferences` stores book-specific reading state under the application preferences directory keyed by content fingerprint; it never edits the original book.

### Shared UI localization

`glim-services::locale` owns message lookup for the Rust UI and the translation payload passed to native previews. English message strings are canonical IDs. `assets/locales/en.json` supplies the fallback catalog; every locale has matching keys and a `__language_name` entry containing its language-name message ID. Catalogs are discovered and embedded by the services build script, and settings enumerates them automatically. Add a complete `<BCP-47-code>.json` file to introduce a language without editing language switches. Explicit language preferences are checked against the discovered catalogs; system matching tries the full locale, then its language, then English.

`scripts/check-locales.py` checks duplicate keys, catalog parity, nonempty translations, interpolation tokens, literal Rust/Swift message references and Chinese text in the English catalog. The services build runs it automatically. Translate application labels and generated preview chrome through the shared catalog; keep user content, paths, application names, language/format names and technical diagnostics intact. Native controls use `L`, Rust uses `locale::tr`; interpolated messages keep their named tokens and HTML output escapes translations. GPUI component-owned controls retain the component library's own locale support; adding a catalog does not supply translations for that library's internal controls.

### Recoverable file removal

`workspace/file_operations` confirms moves to Trash and coordinates the existing cross-window filesystem mutation lock, keeping autosave and Git operations from racing deletion. After success it closes affected live tabs and removes matching workspace roots in every window. Explorer entries and ordinary file tabs expose the action; removing a folder from the workspace remains a separate non-filesystem operation. `glim-services::workspace::trash_entry` runs on the background executor under the save mutex and invokes the bundled native helper's `--trash` mode. Foundation `FileManager.trashItem` handles recoverable, volume-aware moves without following a selected symlink or falling back to permanent deletion.

ImageIO previews defer their initial fit until the embedded view is attached and its scroll viewport has a valid size. Decoding and the first layout share a centered loading state; a zero-sized viewport never commits an almost-zero image scale.

### Browser HTML preview

`reader/markup` retains a `NativeReader` for HTML while keeping the ordinary source editor, saving and reading-mode preferences. HTML source mode does not initialize WebKit until preview is requested; switching back to preview uses the current editor snapshot. `native/HTMLPreview.swift` owns a persistent WKWebView, CSS/JavaScript execution, fragment navigation and a loading/error state. A nonpersistent website data store isolates preview storage. Local links return through the native bridge to Glim's existing file/URL navigation, so the displayed document and source tab do not silently diverge. Popup/dialog overlays and inactive tabs hide the native surface.

A private `glim-html` URL scheme serves the snapshot without project-directory temporary files. Its cancellable serial background reader streams local assets using the shared IO buffer budget; symlink-resolved paths must remain within the enclosing Git project, or the document directory when no Git root is found. The root is discovered and cached on the resource worker, so relative `../` styles/scripts in sibling project directories work without blocking native layout. Network resources use WebKit. The scheme differs from a normal HTTP origin; pages requiring a backend, secure-origin APIs, browser extensions or unrestricted filesystem access may need a development server or a full browser. Large HTML uses the same resource worker to stream the original document instead of building a full editor snapshot. Its editable source pages remain available; save a modified page before returning to preview. WebKit still owns its DOM and script allocations. This browser path is separate from Markdown's static inline-HTML handling and the isolated offline diagram renderer.

## Diagnostics and file failure isolation

`glim-services::diagnostics` owns a bounded background log writer under `~/Library/Logs/Glim/`. Logs use local calendar dates, rotate before 8 MiB per file and retain at most 14 log files (including current-day segments); startup and rotation prune older segments. The bounded queue accepts ordinary messages without blocking rendering; panic records request a synchronous flush with a two-second acknowledgement timeout. Logs include startup/version, file open/read/reader initialization, tab activation, saves and toolkit Info/Warn/Error messages. Panic records include the owning file path, phase, thread, source location and forced backtrace; file contents are not logged. Ordinary queue overflow may drop diagnostic events.

`reader::boundary` attributes the complete lazy file layout/prepaint/paint subtree to a file. The panic hook quarantines that path for the current process. A local patch of pinned `gpui-pre` 0.3.8 (`vendor/gpui-pre/GLIM-PATCH.md`) catches acknowledged file draw panics before the macOS callback, restores entity leases/update depth and the layout engine, discards partial frame state and drawing stacks, and forces a clean frame. The failed file becomes an error page with its full path, retry and log-folder controls; other tabs and unsaved editor entities stay alive. File read and reader-construction unwinds become file failures. Retry is explicit; quarantine resets at app restart. Abort-mode panics, OOM, stack overflow, native exceptions and unrelated app panics are outside this unwind boundary.

### Scalable non-Git readers

`services/geo` streams GPX/KML coordinate pages; `services/xml` decodes XML references consistently for Geo and XLSX. `services/paged` owns editable UTF-8 pages and cancellable atomic range replacement; refresh preserves the current page and unchanged editor state. `services/streamed` recreates canceled codecs and retains a bounded rolling cache. Large cell/schema dialogs use byte windows or disk-backed source pages. Diagram blocks render in active-page batches with complete source retained. Book chapters retain navigation and use full text/hex member pages when structured rendering exceeds working budgets. Native image decoding is serialized and raster output stays within the decoded-memory budget; logical dimensions and full source bytes remain available. This is scaled preview, not region-based full-resolution decoding. SDK allocations, ZIP central-directory indexing and SQLite expression evaluation remain platform/library constraints.

Markdown preview uses TextView’s viewport-bound virtual block list rather than a natural-height whole-document widget. Table normalization only builds an AST when blank-separated pipe rows may need repair. Image and diagram discovery skip AST construction when their required syntax markers are absent. Initial preview text is enqueued after plugin configuration, and empty diagram discovery retains the parser revision to avoid duplicate full parses. Background parsing shows a centered loading state until content is available; state completion refreshes the reader. The minimap seeks and tracks the same virtual list, and anchors use its built-in range reveal. Offscreen blocks are laid out on demand; a single large block still depends on the toolkit’s block layout implementation.

The shared scheduling direction, format-specific representations, current implementation and remaining work are documented in [Rendering pipeline](rendering-pipeline.md). Diagram batches pre-analyze engine dependencies and import only required offline ESM modules; font files use memory mapping and successful raster results share a bounded in-process cache. The asset build embeds the complete module manifest in the app; no runtime project-folder scan is needed.

Markdown workspace refresh also checks referenced local still-image metadata on background workers, even when the Markdown source itself is unchanged. Changed images are decoded again; the old frame remains visible until the replacement is ready. Historical readers and remote images do not participate in this filesystem refresh.

Office and workbook external-open actions resolve the current Launch Services handler at click time. When Glim owns the association, the action offers compatible applications excluding every bundle with Glim’s identifier, plus an application picker. Opening uses an explicit application URL and does not modify file associations; picker selections are checked again to prevent reopening Glim.

Word-processing previews (DOC/DOCX, RTF and Pages) use Quick Look’s normal full-sized presentation within the four-edge reading-area constraints. Slide previews retain the compact undecorated style. This retains the system provider’s document layout; responsive text reflow is not implemented.

Shared reader actions retain their relative ordering across preview and source/data modes: mode selector, content selector, navigation, secondary format controls/status, then external opening. Workbook Cell data places the mode selector before the worksheet selector, matching layout preview. Unavailable actions can be hidden without reordering the remaining actions.
